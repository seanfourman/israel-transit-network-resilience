## שאלות הצעת הפרויקט

| שאלה בהצעה | תשובה נוכחית |
|---|---|
| מה הבעיה שאנחנו פותרים? | מדידת אובדן נגישות בתחבורה ציבורית תחת שיבושי תחנות ומקטעי נסיעה, והמלצת קישורי גיבוי. |
| באילו נתונים נשתמש? | GTFS ישראל: תחנות, קווים, נסיעות, זמני עצירה, לוח שירות, ואופציונלית shapes. |
| איך נקבל את הנתונים? | תיקיית הנתונים במאגר ושחזור Git LFS לקבצים הגדולים. |
| איזו עבודה נבצע? | איחוד תחנות סמוכות לתחנות מאוחדות, בניית גרף, מדדי בסיס, סימולציות שיבוש, המלצת קישורי גיבוי ופרשנות. |
| באילו אלגוריתמים/טכניקות נשתמש? | Union-Find לאיחוד תחנות, מסלולים קצרים, PageRank, betweenness מקורב, נקודות חיתוך, Louvain, בחירה חמדנית של קישורי גיבוי. |
| כיצד נעריך את השיטה? | חלק הרכיב הקשיר הגדול, נגישות בתוך סף זמן, שינוי זמני מסלול, השוואה להסרה אקראית ושיפור לפני/אחרי גיבוי. |
| אם מבוסס על מאמר, מה ההרחבה? | כרגע לא מבוסס על מאמר יחיד; עבודה קשורה תעסוק ברשתות מורכבות, GTFS, מרכזיות ועמידות. |

| עבודה קשורה | רשתות מורכבות, מרכזיות, רשתות תחבורה מבוססות GTFS, עמידות רשתות. |
| מודל / אלגוריתם / שיטה | איחוד תחנות סמוכות לתחנות מאוחדות, בניית גרף, הערכת שיבושים, היוריסטיקת קישורי גיבוי. |
| תוצאות וממצאים | סיכום רשת, פער בין מרכזיות להשפעה, עקומות עמידות, תוצאות שיפור. |
| מסקנות | לקחים מעשיים ומגבלות. |
| תרומות אישיות | ממתין לשמות וחלוקת עבודה אמיתית. |

## משימות מיידיות שנותרו

1. לשחזר את `stop_times.txt`.
2. להתקין תלויות בסביבת עבודה מקומית.
3. להריץ את הפייפליין בגרסה חקירתית.
4. לבדוק תוצאות ולכוון רדיוס איחוד תחנות / סף זמן נגישות.
5. להוסיף סקירת ספרות קצרה עם מקורות.
6. להפוך את הממצאים הראשוניים לסעיפי דוח סופי.
